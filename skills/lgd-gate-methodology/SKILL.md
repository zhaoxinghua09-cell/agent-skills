# LGD-Gate 开源方法论

## When to Use

- 你要从 0 到 1 做一个新的开源工具
- 你要做安全相关的开源项目（扫描器/评测器/门禁工具）
- 你要把自己的理论/框架工程化成可复用的工具
- 你要确保开源项目的质量和安全性

## 核心三律（LGD）

### 1. 有籍（Registered）
每个任务有档案可追溯。
- 每个版本有 CHANGELOG
- 每个决策有记录
- 每个步骤有迹可循

### 2. 有证（Evidenced）
每个结论有出处有证据。
- 每个功能有测试覆盖
- 每个指标有实跑数据
- 每个说法有来源引用

### 3. 有门禁（Gated）
关键节点有检查有验证。
- CI 全绿才能过
- 误报率/召回率达标才能发
- 红队测试通过才能上线

## 完整流程（五步法）

### 第一步：Trending-to-Gap 调研法
1. 看 GitHub Trending，收集相关竞品
2. 拆解每个竞品：做什么、不做什么、优缺点
3. 找到空位：没人做的、做得不够好的
4. 定位机会：现有玩家各做一段，没人串成端到端

### 第二步：Inch-by-Inch 迭代法
1. v1.0 最小可用版——先做一个能跑的
2. v2-v3 加功能——加规则、加语言、加格式
3. v4-v5 加评测——加 benchmark、加红队测试
4. v6-v7 优化质量——降误报率、加覆盖率、做 E2E

### 第三步：Layered-Testing 七层测试法
1. 单元测试——规则数量、版本号、格式输出
2. 集成测试——端到端扫描
3. 错误处理——空文件/二进制/超长行
4. 红队测试——路径遍历/恶意输入/正则 DoS
5. 严格基准——精确率/召回率/F1
6. E2E 模拟——完整用户流程（扫描→修复→再扫描）
7. 压力测试——10000 文件并发

### 第四步：Green-Gate 质量门禁法
1. CI 全绿——所有步骤通过才能算完成
2. OpenSSF Scorecard 高分——10/10 满分
3. 自扫描（dogfooding）——扫自己，看看有没有问题
4. 误报率达标——目标 < 5%

### 第五步：LGD 三律验收
1. 有籍——CHANGELOG 完整，从 v1 到最新版都有记录
2. 有证——每个结论有测试证据，不是吹的
3. 有门禁——关键节点都过了，不是"差不多就行"

## 输出纪律

- 每个版本必须有 CHANGELOG
- 每个指标必须有实跑数据
- 每个结论必须有测试证据
- 不追求一步到位，追求持续改进

## 互相促进闭环（5 个核心功能）

### 1. 自动反馈回路（Feedback Loop）
工具用的过程中发现问题 → 自动记录到"方法论改进建议" → 方法论版本升级。

### 2. 互相打分（Mutual Scoring）
- 方法论给工具打分：功能完整性、稳定性、精度
- 工具给方法论打分：安全性、可执行性、完整性

### 3. 版本同步（Version Sync）
每个工具版本对应哪个方法论版本？方法论升级了，工具要不要跟着升级？

### 4. 自动改进建议（Auto Improvement Suggestions）
每次互相使用完，自动输出：
- 方法论建议工具改进什么
- 工具建议方法论改进什么

### 5. 演进记录（Evolution Log）
完整的迭代历史——每轮做了什么，发现了什么，改了什么。

## Known Limits

- 这套方法学是从做 SkillGate 的过程中沉淀出来的
- 适用于安全/信任相关的开源工具
- 不适用于纯前端/纯 UI 项目
