# 证据链模板（L2 Evidence Chain）

> 判断标准只有一条：**别人拿着这份材料，能不能独立复算出和你一样的结论？**
> 不能复算的，是叙述，不是证据。

## 一条证据必须包含的 7 个字段

| 字段 | 必填 | 说明 | 反例 |
|---|---|---|---|
| `what` | 是 | 改了什么（文件相对路径） | "改了配置文件"（哪个？） |
| `before` | 是 | 改前 SHA-256 | "原来是对的"（不算指纹） |
| `after` | 是 | 改后 SHA-256 | 无 |
| `how` | 是 | 怎么产生的（工具/命令/模型） | "AI 改的"（哪一步？） |
| `ts_utc` | 是 | UTC 时间戳 | 只有本地时间（跨时区无法对账） |
| `ts_local` | 是 | 本地时间戳带时区 | 手写日期（可伪造） |
| `recompute` | 是 | 复算命令，任何人可跑 | 无 |

## 机器可读形态（推荐：JSONL，只增不改）

```json
{"kind":"snapshot","task_id":"T-20261106153000","note":"统一改排版",
 "files":{"docs/a.md":{"sha256":"a680f0ed9afc...","size":1024}},
 "delta":{"added":[],"modified":["docs/a.md"],"removed":[]},
 "ts_utc":"2026-11-06T07:30:12Z","ts_local":"2026-11-06 15:30:12 +0800"}
```

一行一条，追加写，不修改历史行。**只增不改是证据链的底线**——能改的台账不叫台账。

## 人可读形态（对外举证用）

```markdown
## 变更记录

| 时间(UTC) | 文件 | 改前指纹 | 改后指纹 | 产生方式 |
|---|---|---|---|---|
| 2026-11-06T07:30:12Z | docs/a.md | a680f0ed9afc | a5de2203f29c | audit_chain.py seal |

复算：`python scripts/audit_chain.py verify --root .`
```

## 三层证据的分工（别混）

| 层 | 回答什么 | 载体 | 谁看 |
|---|---|---|---|
| L1 籍 | 这件事谁批的、依据什么 | `registry.jsonl` | 内部管理 / 审计员 |
| L2 证 | 具体改了什么、怎么复算 | `evidence.jsonl` | 审计 / 举证现场 |
| L3 门 | 高危动作谁放行的 | `gates.jsonl` | 监管 / 事故复盘 |

**常见错误是把三层合并成一份"治理报告"**——合了就分不清"谁批的"和"改了什么"，出问题时无法定位责任环节。

## 证据链的最小可信条件

1. **时序单调**：时间戳不能被后来的记录覆盖或倒填
2. **内容可复算**：给出命令，别人跑出同样结果
3. **范围明确**：一条链只管一个范围（一个项目/一个交付），不混装
4. **脱敏**：不含口令、密钥、身份证号、客户报价原文

## 何时需要更强证据

本地指纹 + 时间戳足以应对**内部审计与自证**。以下情形需要外部锚定：

| 情形 | 需要什么 | 说明 |
|---|---|---|
| 对外诉讼举证 | 可信时间戳（RFC 3161 TSA）或公证 | 本地时间可被质疑 |
| 跨组织互认 | 第三方存证 / 区块链锚定 | 双方都不信对方台账 |
| 监管报送 | 按监管指定格式与平台 | 格式由监管定，不是我们定 |

本技能**不提供**这三类外部锚定，只提供可对接的材料层。需要时另行接入，不要声称已具备。
