# 来源适配（adapters）

同一场会，从五个地方倒出来的格式都不一样。`adapt` 先认来源，再折成「人：话」一行一句，
之后 extract / citecheck 才判得准。**只认不改等于没适配**——这是本节的实际教训。

## 识别规则

| 来源 | 命中信号 | 折行处理 |
|---|---|---|
| 腾讯会议 | `腾讯会议`／`会议主题：`／`参会人：`／`XX 的发言` + 时间戳 | `XX 的发言 00:01:12` → `XX：`，并与下一行内容合并 |
| 飞书妙记 | `妙记`／`[hh:mm:ss]`／`发言人 N` | 去掉行首时间戳，`发言人 N` 独占行 → 合并下一行 |
| Kimi Work | `Kimi Work`／`**说话人**` | `**张三**` → `张三：` 并合并下一行 |
| WorkBuddy | `WorkBuddy`／`## 会议纪要` | 已是纪要结构，**建议直接 citecheck，不再 extract** |
| Word (.docx) | 扩展名 | 段落已抽取；表格内容不在段落里，有表格请另存 md |
| 纯文本 | 无平台特征 | 原样处理，检查说话人前缀是否齐全 |

## 用法

```bash
# 只识别（不动文件）
python scripts/summarize_pro.py adapt --file 会议.md

# 识别 + 折行，写出规范化文本，再抽取
python scripts/summarize_pro.py adapt --file 会议.md --normalize --out 会议.norm.md
python scripts/summarize_pro.py extract --file 会议.norm.md --format minutes
```

## 为什么必须折行

腾讯会议把「陈涛 的发言 00:01:12」和说话内容分成两行。若只做识别不做折行：
说话人检出 1 个（应为 4 个），待办句检出 0（应为 1 个）——主语与内容分家，判不出「谁接活」。

实测（本包自带样本 `_t_tencent.md`）：

| 指标 | 折行前 | 折行后 |
|---|---|---|
| 说话人行 | 1 | 4 |
| 待办句 | 0 | 1 |

## 边界

- 不猜姓名：发言人未知时保留「发言人 N」，不推断真人。
- 不删时间戳：时间戳是证据锚点，折行时搬到句首或保留在原位，不丢弃。
- 不改写内容：折行只动版式，一个字都不改；需要改写请人工确认。
